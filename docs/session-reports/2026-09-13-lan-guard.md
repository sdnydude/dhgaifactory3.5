# LAN guard (plan 5.3) and cloudflared metrics (5.4) — 2026-09-13, 22:24–23:00 ET

## Story

A short session picking up the handoff's item 2: the two root-only follow-throughs from the observability rebuild. The first, cloudflared `--metrics` flags, turned out to be already done — both units carried `--metrics 0.0.0.0:2024x`, both listened on all interfaces, both Prometheus targets were UP — so the runbook and the `prometheus.yml` job comment were the only things still saying "DOWN by design". Ticked and corrected.

The second, the runbook's ufw recipe for limiting Prometheus, Alertmanager, Loki and cAdvisor to the Mac, failed on three facts read off the host before writing anything: ufw is disabled (`/etc/ufw/ufw.conf` ENABLED=no); Docker DNATs a published port in nat PREROUTING, so LAN traffic traverses FORWARD and never the INPUT chain ufw writes to; and dh40801's Alloy pushes logs to `10.0.0.251:3100`, which the recipe would have cut. Stephen asked "why skip?" ufw, took the answer (it cannot see the traffic, and enabling default-deny is a separate port-map project), and agreed to the narrow build.

`observability/scripts/docker-user-fw.sh` installs one `DHG-LAN-GUARD` chain, jumped from `DOCKER-USER` for v4 and from `INPUT` for v6 (the `[::]` listeners are docker-proxy sockets, no DNAT). Two details mattered: cAdvisor's container port is 8080, the same as open-webui's (published on 3080), so the match is on the conntrack ORIGINAL destination port rather than `--dport`; and Prometheus on this host scrapes dh40801:8080, whose reply packets would have matched the 8080 DROP, so a RELATED,ESTABLISHED RETURN sits before the drops. The unit runs a root-owned copy under `/usr/local/sbin` because a root systemd unit must not execute a user-writable file, and is `PartOf=docker.service` so a Docker restart re-applies it. Four bats tests (suite 44/44) plus a real-iptables exercise in a throwaway NET_ADMIN container (the host's AppArmor blocks unprivileged user namespaces).

The first hand-over line used relative paths and Stephen ran it from `~`; nothing installed, and the absolute-path line went in cleanly at 22:52. Verification: from dh40801, 9090 and 8080 time out while 3100 and 3001 answer; all dh40801-facing scrape targets stay UP; a probe container log line emitted on dh40801 landed in Loki through the guard; the frontend's Prometheus proxy still answers 200. Committed on a branch, merged `--no-ff`, pushed (master 88783168).
